**GPT Switch** は、Windows と SSH 接続先の Linux で Codex の設定を管理する GUI ツールです。CC Switch でローカルの接続を変更した後、必要な設定と対応する認証情報を、信頼できるリモートホストへ同期できます。

**接続同期は新規チャットの接続先を変更し、チャット移行は保存済みレコードのモデル・プロバイダーを変更します。別々の操作です。**

> **2.6 はユーザー受け入れテスト待ちのローカルプレビュー版です。まだ公開されていません。** OpenAI の公式製品ではありません。現在の GUI は簡体字中国語です。ドキュメントは英語・中国語・日本語・ドイツ語に対応します。

## 主な機能

| 機能 | 内容 |
| --- | --- |
| ローカル接続への追従 | CC Switch が書き込んだ Codex 設定から必要な項目だけを同期 |
| 認証状態の検証 | ファイル更新、アカウント確認、認証情報の読み込み、`workspace-401` を区別 |
| デバイスコード認証 | 対応するアカウントで、リモート側の独立した ChatGPT ログインを開始 |
| 既存チャット移行 | `model` / `model_provider` をプレビューして一括更新。アーカイブ済みも対象 |
| SSH 修復 | 対象 PID の確認、バックアップ、承認済みプロセスの停止、更新、再確認 |
| 復元可能な変更 | SQLite スナップショット、認証ファイルの保護、古いプレビューの拒否、書き込み失敗時の復元 |

## クイックスタート

- ローカル：Windows、Tcl/Tk を含む Python **3.11 または 3.12**。
- リモート：Linux、同期には Python **3.10+**。プロセス診断のみ Python 3.6+ でも利用可能。
- Windows OpenSSH で非対話ログインを設定してください。初回のホスト鍵確認は先にターミナルで行います。

```powershell
git clone https://github.com/hialoha/gpt-switch.git
cd gpt-switch
.\start.cmd
```

`pip install` は不要です。利用可能な Codex 同梱 Python、次に PATH の `python` を使用します。起動エラーの確認には `python app.py` を実行します。未公開の 2.6 を試す場合は、提供されたローカルテスト版を使用してください。

## 接続と認証の同期

1. CC Switch で切り替え、**ローカルの新規チャット**が動くことを確認します。
2. **SSH 远端同步…** でホストを選び、**跟随本机连接与登录态…** を開きます。
3. **预览本机 → 远端** で接続先、認証方式、エンドポイント、停止対象を確認します。プレビューでは認証情報そのものは転送しません。
4. **备份并同步配置与登录态** を押すと、バックアップ後、表示されたホストへ SSH で認証情報を転送します。
5. 検証結果を確認し、SSH プロジェクトへ再接続して**新規リモートチャット**を試します。
6. ChatGPT の `workspace-401` が残る場合は、下部のデバイスコード認証を利用し、公式ページで認証してから再検証します。アカウント・ワークスペースで許可されている必要があります。

同期するのはモデル、プロバイダー、エンドポイント、関連する認証設定、任意のモデルカタログです。ファイル形式の ChatGPT キャッシュと、選択されたプロバイダーの API キーに対応します。選択された環境変数のキーはリモートのファイル認証へ変換されます。アクティブな profile の古い接続設定も更新します。

リモートのプロジェクト、MCP、プラグイン、権限、サンドボックス、無関係な環境変数は維持します。TOML は再シリアライズするため、**コメントや書式が変わる場合があります**。元ファイルは完全にバックアップします。

Windows の資格情報ストアやメモリ内の認証、外部認証ヘルパーは無条件には転送しません。ChatGPT トークンはカスタムプロキシ設定へコピーしません。ローカルの HTTP / ループバック URL はそのままリモートでは利用できません。

## 既存チャット

接続同期後も既存チャットに古い設定が残る場合は **一键修复远端…** を使います。レコードと具体的な PID を確認してから、バックアップ → 停止 → トランザクション更新 → 再確認を行います。内部自動レビューは変更しません。

プロセスの親や、自動再起動した新しい PID は停止しません。接続を占有し続ける場合は、そのホストへの Codex / VS Code のリモート接続を切断してください。

モデル一覧は推論権限の保証ではありません。接続検証はチャット推論を送信せず、API キーでは読み込み確認にとどまる場合があります。実際の新規チャットでも確認してください。ファイルのコピーでワークスペース権限を付与することはできません。

## バックアップと安全性

- 設定・認証：`<CODEX_HOME>/gpt-switch-config-backups/<timestamp>/`。
- チャット DB：データベース横の `gpt-switch-backups/`。
- ローカルの脱敏済み完了記録：ツールの `ssh-results/`。認証情報パッケージは保存しません。

認証ファイルは `0600`、設定バックアップディレクトリは `0700` です。バックアップにも利用可能な認証情報が含まれます。信頼できるホスト・ユーザーだけに転送し、Git や Issue に添付しないでください。コピーしたログイン状態は更新や期限切れで分岐するため、独立したリモート認証が必要になる場合があります。

関連バックエンドの停止後、接続ウィンドウから直前の設定バックアップを復元できます。DB の手動復元では現在の SQLite/WAL/SHM を別途保存し、スナップショットを戻して古い WAL/SHM を移動してから再起動します。完全復元はバックアップ以降の変更も巻き戻します。

書き込み中に接続が切れたら、即座に再実行せず、先に検証してください。主ウィンドウの X は終了し、送信済み書き込みを待ち、追跡中のデバイスコード認証の取消を試みます。ネットワーク障害時は取消できない場合があります。

## トラブルシューティング

- **新規チャットが旧プロバイダーへ接続する**：チャット移行だけでなく、接続同期を使用し、profile・起動引数・環境の上書きを確認します。
- **`workspace-401`**：リモートログインとワークスペースの権限を確認し、必要ならデバイスコードで再認証します。
- **古いモデルが表示される**：PATH が古い CLI を指している可能性があります。選択したパスとバージョンを確認します。リモートの検査は目標値を勝手に変更しません。
- **keyring / 認証ヘルパー**：対応するファイルキャッシュまたは独立したリモートログインを使います。
